# 父会话派单提示词

功能单先核对用户已批准的整组修订。前后端使用同一任务包的 task.md、acceptance.md、需求共用规则及本端说明（如有）。涉及接口时 Backend 先写 api.md，前端依同版定义对接。派单附相关上游产物和验收条件；从父目录提供可读的绝对路径或对应正文，不发送整个需求目录、对端 spec 或父会话历史。本端 reviewer 沿用同一组输入。修复单则传原症状与失败修复段，不为已授权的修复补建功能 spec。

## 实现与修复单的公共正文

从 Matt 派发和从前后端 bot 直接接单都按[认领、派发和回执](claims.md)查重、登记本单授权并取得唯一执行权。派单附任务键、本批修订、当前阶段、开发证据、仅联调所需条件、返回会话。已有任务的咨询在来问的会话答复，返修续接原执行者和原树。

部分批准时，正文写清本单允许实施的 ID 和仍待批准的范围，如「本次只实现 T01，T02 待批」。完整公共 spec 提供契约上下文，实施范围以该批准记录为准。

直收任务先判断用户意图。只问或只排查，核实对应版本并在原会话交付结论。明确的本端修复先按 diagnosing-bugs 复现定位，再按下文回归和重跑原操作；范围清楚的局部改动按用户说明的预期验证。直收者负责联络 Quality 并向用户交回结果，可用轻量修复记录。新增业务行为、需变更公共契约或另一仓库时，把已知证据、相关任务和待决问题交 Matt 统一澄清、确认批准范围，保留原会话的返回地址。

**Orca bot 团队适配。** 会话解析命令追加 `--host orca`，本次指定模型时追加 `--model <模型或别名>`。`model: null` 直接省略 worker 的 `--model`；本节后文的 `inherit` 模型继承约定只用于其他宿主。Orca 中由前端/后端 bot 接实现单，Quality 组织两轴审查，交接和 worker 模型参数按 bot 安装的 `matt-orca` skill 执行。

派发者在共同父目录执行 `node .matt/runtime/sessions.mjs <角色>`，分别取本端（`frontend` 或 `backend`）及 `standards`、`spec` 设置。首次派单使用独立上下文的 subagent 或会话，只发本单；`inherit` 继承模型而非对话。`worktree: true` 时按[工作树指南](worktrees.md)固定起始提交和最终目标，由宿主创建并绑定工作树，随单传核对基线和初始化要求；`false` 复用指定 checkout。记录会话引用、模型来源和宿主已报告的实际模型（如有）、实际目录和 HEAD；无法满足时输出待派提示词。

> 你的工作目录是 `<本端 checkout 绝对路径>`，基线是 `<本端起始 SHA>`。遵循本仓指令，只编辑本单涉及的实现和测试。交付依据是 `<获批任务包的入口、验收用例、适用接口、整组修订与场景 ID，或修复单中的原症状与预期>`。技术接口修改在原 api.md 同步相关端。用户可见行为或范围有变时，交 Matt 澄清后继续受影响的工作。有关联工单时附 `<完整 URL 或父目录相对路径、标题>`；按共享规则核对，审查和交接沿用此引用。自动派单直接按下面的 TDD、测试和审查步骤工作，无需用户再触发实现技能。
>
> 共享约定：`<workspaceRoot>` 是父目录，不是本端 checkout。从父目录运行 `.matt/runtime/docs.mjs`，随单交付解析出的共用规则、本任务包、工单及领域约定的绝对路径、修订及所需术语表/ADR；涉及 triage 时附标签规则。工单的相对路径和远程仓库归属以父层配置为准，不按本端 remote 推断。向两路 reviewer 转交相同约定和交付依据；独立 worktree 无权读取时，由派发者附所需的非敏感原文和来源，不在子仓另建配置。
>
> 通过 `$mattpocock-skills:tdd` 在 `<本端已确认的公开边界>` 逐个验证行为，先观察失败，再做最小实现。若尚需设计公开接口，调用 `$mattpocock-skills:codebase-design`，将会影响另一端的决定交给父会话。开发期间运行类型检查和单项测试，最后运行该仓完整测试。
>
> 按[审查分流](review.md)选择提交或补丁审查，应用 `<standards 和 spec 角色解析结果>`；派发者随单传入该指南在父层的可读绝对路径或正文。模型可调用的技能若无宿主入口，可读取派发者提供的随包技能绝对路径并注明来源。
>
> 交回最终 SHA 或补丁摘要、对应场景或故障、测试命令和结果、两轴审查结果、启动或迁移条件、未验证项。另一端未完成时也请先交接本端。

## 前端角色段

> 你负责 `<页面与用户操作>`。请从路由表、权限守卫和客户端请求自行定位实际页面。实现 `<操作后可见的成功状态>` 以及 `<失败或权限变化时的可见状态>`，覆盖 `<前端场景 ID>`。说清哪些行为用了接口替身，给出父会话连接真实测试后端时需要的地址配置和页面入口。

## 后端角色段

> 你负责 `<接口与领域行为>`。按公共契约实现 `<请求/响应、授权和失败语义>`，通过 `<公开 API 或服务接口>` 验证 `<后端场景 ID>`。交回迁移与启动条件、健康检查，以及父会话在测试环境准备和清理合成数据的方法。

Orca 实现单或直收修复涉及改开发库时，随单提供共享需求目录。按团队协议「开发库 SQL」由 Backend 准备脚本、Matt 发起人工确认、Backend 凭批准编号执行。Quality 按业务行为验收。

## 失败修复段（用户报障或 E2E 失败）

> 原始复现是 `<环境、操作或命令、预期、实际、脱敏证据>`；责任判断依据是 `<根因与定位证据>`。这是本单两轴审查的行为依据。若有已有契约、版本对、失败 case 或本地私有报告，随单引用。优先续接原会话和工作树；首次报障或原会话不可用时带本单及已有交接新开责任端会话。
>
> 在能捕获原症状的公开边界先写回归测试，看到失败再修复；若没有合适边界，说明缺口，保留原复现，不用无关绿测替代。交回新版本或补丁及证据，由父会话核对修复版本并重跑原复现。
