# 父会话派单提示词

本模板只用于已授权的产品改动。功能单发送公共正文和本端角色段；修复单发送公共正文和失败修复段，无需先建功能 spec。按实际情况填入所需字段，不要求补齐不存在的 E2E 材料。

## 实现与修复单的公共正文

派发者在共同父目录执行 `node .matt/runtime/sessions.mjs <角色>`，分别取本端（`frontend` 或 `backend`）及 `standards`、`spec` 设置。`worktree: true` 时将实现会话绑定到从本端派单 SHA 创建的独立工作树；`false` 复用指定 checkout。`inherit` 继承直接派发者的模型。记录会话引用、宿主确认的模型、实际目录和 HEAD；能力不足时输出带模型和 checkout 的待派单。

> 你的工作目录是 `<本端 checkout 绝对路径>`，基线是 `<本端起始 SHA>`。遵循本仓指令，只编辑本单涉及的实现和测试。交付依据是 `<本端任务单与公共 spec 修订/场景 ID，或修复单中的原症状与预期>`。有工单时附 `<父会话确认的完整 URL 或父目录相对路径、标题>`；按共享规则读取核对，审查和交接沿用此引用。自动派单直接按下面的 TDD、测试和审查步骤工作，无需用户再触发实现技能。
>
> 共享约定：`<workspaceRoot>` 是父目录，不是本端 checkout。从那里读取 `<工单规则、领域文档规则及相关术语表/ADR 的绝对路径>`；涉及 triage 时附标签规则。工单的相对路径和远程仓库归属以父层配置为准，不按本端 remote 推断。向两路 reviewer 转交相同约定和交付依据；独立 worktree 无权读取时，由派发者附所需的非敏感原文和来源，不在子仓另建配置。
>
> 通过 `$mattpocock-skills:tdd` 在 `<本端已确认的公开边界>` 逐个验证行为，先观察失败，再做最小实现。若尚需设计公开接口，调用 `$mattpocock-skills:codebase-design`，将会影响另一端的决定交给父会话。开发期间运行类型检查和单项测试，最后运行该仓完整测试。
>
> 按[审查分流](review.md)选择提交或补丁审查，应用 `<standards 和 spec 角色解析结果>`；派发者随单传入该指南在父层的可读绝对路径或正文。模型可调用的技能若无宿主入口，可读取派发者提供的随包技能绝对路径并注明来源。
>
> 交回最终 SHA 或补丁摘要、对应场景或故障、测试命令和结果、两轴审查结果、启动或迁移条件、未验证项。另一端未完成时也请先交接本端。

## 前端角色段

> 你负责 `<页面与用户操作>`。请从路由表、权限守卫和客户端请求自行定位实际页面。实现 `<操作后可见的成功状态>` 以及 `<失败或权限变化时的可见状态>`，覆盖 `<前端场景 ID>`。说清哪些行为用了接口替身，给出父会话连接真实测试后端时需要的地址配置和页面入口。

## 后端角色段

> 你负责 `<接口与领域行为>`。按公共契约实现 `<请求/响应、授权和失败语义>`，通过 `<公开 API 或服务接口>` 验证 `<后端场景 ID>`。交回迁移与启动条件、健康检查，以及父会话在测试环境准备和清理合成数据的方法。

## 失败修复段（用户报障或 E2E 失败）

> 原始复现是 `<环境、操作或命令、预期、实际、脱敏证据>`；责任判断依据是 `<根因与定位证据>`。这是本单两轴审查的行为依据。若有已有契约、版本对、失败 case 或本地私有报告，随单引用。优先续接原会话和工作树；首次报障或原会话不可用时带本单及已有交接新开责任端会话。
>
> 在能捕获原症状的公开边界先写回归测试，看到失败再修复；若没有合适边界，说明缺口，保留原复现，不用无关绿测替代。交回新版本或补丁及证据，由父会话核对修复版本并重跑原复现。
