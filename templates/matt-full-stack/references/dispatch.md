# 父会话派单提示词

本模板只用于需要修改产品代码的实现或修复单。给每个受影响的端发送公共正文和对应角色段（修复时附失败修复段），替换所有尖括号。使用本端仓库绝对路径、派发前的 HEAD 和已约定的测试边界，公共 spec 使用修订号或内容摘要。原会话不可继续时，新会话接收同一修复单、原交接和已定位证据。

## 实现与修复单的公共正文

派发者先应用本角色解析出的设置。`worktree: true` 表示以本端仓库和派单 SHA 为基线创建独立 Git 工作树，并把新会话 cwd 绑定到它。`false` 表示复用指定 checkout。`inherit` 表示继承直接派发者的模型，其他值传给宿主的模型选择参数。启动后记录宿主能确认的模型、实际工作目录和 HEAD。能力不足时输出待派单、所需模型和 checkout，供其他工具或手动启动。修复优先复用原会话及工作树。

> 请显式调用 `$mattpocock-skills:implement`。你的工作目录是 `<本端仓库绝对路径>`，遵循该仓指令，只编辑本端实现和测试。公共 spec 在 `<spec 绝对路径及修订>`，接口版本为 `<版本>`，验收用例在 `<YAML 绝对路径和 case ID>`。父会话维护这些公共文件。若插件名不可用，请读取父会话提供的 `<上游工具包绝对路径>/vendor/mattpocock/<对应短名>/SKILL.md` 及引用。
>
> 你启动 `code-review` 的两个 reviewer 时，分别应用 `<standards 角色解析结果>` 和 `<spec 角色解析结果>`。两者使用独立上下文，只读审查同一份实际改动。共享模式使用你的实现 checkout；独立 worktree 使用待审 HEAD，如有未提交改动还需提供完整补丁（含新增文件）。若宿主无法启动嵌套 reviewer，把两份带配置的审查单交回父会话代派，`inherit` 仍取本端实现会话的模型。无法满足配置时记录待派发项。
>
> 通过 `$mattpocock-skills:tdd` 在 `<本端已确认的公开边界>` 逐个验证行为，先观察失败，再做最小实现。若尚需设计公开接口，调用 `$mattpocock-skills:codebase-design`，将会影响另一端的决定交给父会话。开发期间运行类型检查和单项测试，最后运行该仓完整测试。
>
> 完成后显式调用 `$mattpocock-skills:code-review`，基线是 `<本端起始 SHA>`，规范来源是本仓指令，Spec 轴使用上述公共 spec。分别报告 Standards 和 Spec 结果。按授权提交时，确保待审改动已包含在基线到 HEAD 的 diff 内，按发现修复并复测。若只能交付工作树，则提供实际补丁（含新增文件），按两轴审查该补丁并注明审查范围。缺少独立审查能力时，注明实际执行的审查方式。
>
> 交回实际 SHA 或未提交差异、对应 case ID、测试命令和结果、两轴审查与修复结果、启动或迁移条件、所需合成数据、未验证项。另一端未完成时也请先交接本端。

## 前端角色段

> 你负责 `<页面与用户操作>`。请从路由表、权限守卫和客户端请求自行定位实际页面。实现 `<操作后可见的成功状态>` 以及 `<失败或权限变化时的可见状态>`，覆盖 `<前端场景 ID>`。说清哪些行为用了接口替身，给出父会话连接真实测试后端时需要的地址配置和页面入口。

## 后端角色段

> 你负责 `<接口与领域行为>`。按公共契约实现 `<请求/响应、授权和失败语义>`，通过 `<公开 API 或服务接口>` 验证 `<后端场景 ID>`。交回迁移与启动条件、健康检查，以及父会话在测试环境准备和清理合成数据的方法。

## 失败修复段（回到责任端原会话）

> 请继续处理 `<场景 ID / 失败步骤>`。实际运行组合为前端 `<SHA/构建号>` 与后端 `<SHA/构建号>`。复现操作是 `<步骤及合成数据标识>`，契约预期为 `<预期>`，实际为 `<现象>`。责任判断依据为 `<脱敏的页面及接口证据>`，报告位于 `<本地私有路径>`。沿用原 spec 与约定边界，本次修复审查基线为 `<修复前本端 SHA>`。
>
> 若根因尚未证实，先调用 `$mattpocock-skills:diagnosing-bugs` 建立可重复的失败检查。按公共正文执行 `$mattpocock-skills:implement`、`$mattpocock-skills:tdd` 与 `$mattpocock-skills:code-review`。先用回归测试复现这一现象，再修复、复测并交回新版本、证据和受影响场景。父会话负责在新版本组合上复验。
