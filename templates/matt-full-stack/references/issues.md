# 从接单到交付使用同一工单引用

**父会话确认来源。** 从父层 `## Agent skills` 指向的工单规则读取 tracker 和项目。远程工单用含主机、完整项目路径和编号的 URL；本地 Markdown 用相对共同父目录的完整文件路径。遇到 `#123`，只有规则或用户明确了唯一项目才展开。即使只改前端，前端仓也不一定是工单仓。归属有多种解释或与用户给的引用冲突时，只问归属，不按当前目录、子仓 remote 或同号搜索结果猜。

按规则从这个地址读取，核对标题和正文是否对应当前需求。远程读写显式指定已确认项目（如 `gh issue view <完整URL>`）；本地路径从父目录解析。读取失败或内容不符，标明哪张单未核实，请用户澄清或提供可核实的内容，不另挑一张同号单继续。若项目要求先建单，先查有无可复用的工单；没有才按项目约定和已获授权创建。缺少写入授权则给出拟建项目、标题和正文，停在需要工单的步骤。

**随交付传递。** 将完整引用和标题记入公共 spec 的「需求来源」（旧模板没有此栏就加在本次需求文档里）；修复单直接记录，不为排障补建 spec。向责任端和 reviewer 传同一引用，以及公共 spec 路径、修订和场景，或原症状与预期。工单说明需求来源，跨端接口和验收场景只在公共 spec 维护。两者不一致先确认，不另抄一套契约。

**回报不等于回写。** 审查、交接和父会话的最终报告都保留完整引用，标出实际版本、已验证与未验证项。仅在用户要求或项目约定需要、且已有对应写入授权时，由父会话在同一张单上回写脱敏结论。未获授权就交付待回写摘要；不把实现、测试或审查完成视为关单授权。
