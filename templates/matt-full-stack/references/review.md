# 先固定待审内容，再派两路审查

在**本端实际 checkout** 对照派单时的起始 SHA、`git status --short --untracked-files=all` 和本单文件清单。区分本单与用户原有改动，重命名核对新旧路径。范围不清先问，不为制造可审 diff 而暂存、提交或夹带他人改动。以下二选一。

**提交审查。** 若本单改动已全部提交（或已授权、已仅提交本单内容），记录起始 SHA 和待审 HEAD SHA。确认 `git diff <起始SHA>...<待审SHA>` 非空且覆盖本单，两个 reviewer 的 HEAD 都是这个待审 SHA，再调用 `$mattpocock-skills:code-review`，以起始 SHA 为固定点。不要用部分提交覆盖剩余工作树改动。

**补丁审查。** 只要本单还有未提交内容，就交付从起始 SHA 到本次最终文件状态的一份完整补丁，不调用只读 `...HEAD` 的原版入口。在仓库根目录用以下 Git 命令生成，路径换成本单逐一确认的文件，补丁保存在 checkout 外的本地私有位置：

- 已跟踪路径（含删除）：`git diff --binary --no-ext-diff --no-textconv <起始SHA> -- <本单路径…>`。这里刻意不用 `--cached` 或 `...HEAD`，以包含已提交、已暂存及未暂存的最终差异。
- 未跟踪的新文件：逐个追加 `git diff --no-index --binary --no-ext-diff --no-textconv -- /dev/null <新文件>` 的输出；此命令退出 1 表示有差异。只收本单文件，不附私钥、凭据或私有报告。
- 核对 `git apply --stat <补丁>` 与本单清单一致；用干净的基线 checkout 执行 `git apply --check <补丁>` 验证补丁可用，记录补丁摘要。将**同一份补丁**和基线交给两个只读 reviewer；独立 worktree 绑定起始 SHA，审查输入是补丁，不是它的 HEAD diff。无法分离同一文件中的他人改动或拿不到完整补丁，标记审查阻塞。

两种模式均使用 `standards`、`spec` 的配置和独立上下文，并行审查、分别报告。补丁模式沿用两轴标准：Standards 按本仓规范和 Matt 的代码异味基线，Spec 按任务单/修复预期与公共契约；标明是**补丁审查**。若宿主无法嵌套派审，交父会话代派，继承模型仍取本端实现会话的模型；无法完成的审查列为待办，不报通过。若审后有修改，重新固定最终 SHA 或生成新补丁、复测并复审，不用旧报告签收新改动。
