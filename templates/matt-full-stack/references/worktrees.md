# 任务工作树、试合并与收尾

## 开工与续接

每项独立派发的实现任务在每个涉及的仓库各有一个写入方。角色启用 `worktree` 时，由宿主原生创建并绑定任务分支和工作树；共享 checkout 按[派单记录](claims.md)串行。跨端一项用两个仓各自的树，同仓两项独立任务各用一棵树，同一任务的阶段和返修复用原树。

1. 从消费父目录运行 `node .matt/runtime/sessions.mjs <frontend|backend> --worktree-base`（Orca 追加 `--host orca`）。记录本端原 checkout、branch、sha、dirty 及最终目标 targetBranch、targetSha。默认目标是本端当前分支，指定其他已约定的本地目标用 `--target-branch <分支>`。本端处于 detached HEAD、尚无提交或目录无法核实时，须先确认基线。
2. 实际开工点为 startSha。独立任务默认从目标提交开始。依赖前序代码时追加 `--requires-sha <前序交付的本仓完整提交>`，多项可重复。需要组合起点时追加 `--start-sha <已核实提交>`，解析器核对它包含每项指定依赖。核对起点到目标的差异，排除无关的未合入工作。依赖只有补丁、未提交的本地改动或属于另一仓时，分别等待同仓提交或登记为跨仓交付条件。
3. 先取得 start 回执。Orca 选择本仓，从 startSha 创建独立任务分支，使用 `--setup inherit`，由 Orca 执行仓库 `orca.yaml` 的策略。成功回执对应的一次初始化供所有阶段复用。创建结果不明时先用任务分支、工作树 ID 及原运行回执查找；钩子仍在运行则等待，失败则记录具体步骤。其他宿主优先复用成功的创建钩子，剩余初始化按仓库约定完成。
4. 在新会话核对原、新 checkout 的 `git rev-parse --path-format=absolute --git-common-dir` 指向同一仓，实际根目录独立，任务分支有名且不同于目标，`git rev-parse HEAD` 等于 startSha。不能原生绑定则记为待派。登记真实分支、目录、工作树 ID、worker、初始化结果及进度；返修先核对这些记录。保持同事的工作区、未提交改动与无关 PR 完整。

只读 reviewer 按[审查指南](review.md)绑定待审提交或基线加核实过的完整补丁，并记录实际输入。只读审查工作树没有待合回的实现分支。

## 与同事的改动试合并

1. 按实际依赖排序。核对记录中的本地目标，读取该分支配置的 upstream（`git branch -vv`）。如有共享远端，先 fetch 对应远端，核对实际跟踪分支、是否仍存在及双方提交。用 `git rev-list --left-right --count <本地目标SHA>...<上游SHA>` 判断前移或分叉。记下本地、上游及项目约定的实际落地目标 SHA。存在分叉时明确两侧应纳入的变更；仅在本任务明确依赖时纳入尚未合入的同事分支。
2. 由宿主准备隔离的试合并工作树，在核实的目标上合入本批选定的任务提交，记录各输入及试合并结果 SHA。已有提交可用快进；存在分叉时保留双方意图。只有补丁时先按[审查指南](review.md)验证完整性，形成可合并提交需有相应授权。在试合并及测试期间，目标分支保持原位。
3. 文本冲突由原实现 bot 查阅两侧提交、工单、PR、已有测试和批准的规格。整合可兼容的技术变化，分别验证双方行为。业务预期互斥时，Matt 列出具体分歧、选项和影响，请用户或规则负责人决定。Git 自动合并成功也要验证交叉行为，例如目标新增权限校验，任务新增批量入口，两个入口均须拒绝无权限操作。
4. Quality 对固定组合做规范、规格审查，核对本端回归。如果启用 E2E，用预定用例验证实际运行的两端候选版本。测试服务和下游使用某个任务目录前，用 `tasks.mjs use <键> --at <版本> --actor <使用者>` 登记；退出并释放目录后用同样参数和最新版本执行 `release`。只引用已固定的提交不占用目录。

## 合回与清理

向用户列出每项的任务分支及 SHA、目标与试合并 SHA、上游、实际版本组合、测试和未验证项，询问选择哪些合回、哪些清理。两项可一起或分别授权。合回前再次 fetch 并核对本地目标、上游、任务与候选内容；任何输入前移都重新组合、复验受影响部分，并更新授权所基于的版本。目标 checkout 脏则保留现场，采用项目已有的 PR 或合并队列等路径。实际落地应与受验内容一致，记录最终 SHA；推送、发布、关单按各自授权执行。

清理前核对指定目录确实属于该任务、所需验证通过、改动已合入、树干净，以及 worker、下游和服务已释放。一般合并可用 `git merge-base --is-ancestor <任务SHA> <实际落地SHA>` 核实；squash、rebase 等路径核对实际 PR 的合入记录及最终内容。保留分支上的新提交、未提交改动及仍待返修的现场。

确认清理授权和上述证据后，用 `tasks.mjs cleanup <键> --at <版本> --actor <清理会话> --evidence "<核对记录>"` 锁定收尾；已登记使用者会阻止此步。再次对照现场，Orca 用 `worktree rm --worktree <明确的工作树ID>`，依项目约定执行归档钩子。只在宿主支持保留任务分支时按此方式清理，删分支另需相应授权。成功后用同样的参数和最新版本执行 `removed` 登记回执；决定保留则用 `retain` 登记原因。回执不明先核对实际树和分支，再恢复记录。
