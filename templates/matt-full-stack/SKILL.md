## 先确定交付物

日常入口是 `$matt-full-stack` 加需求描述。使用 Matt 工程 skill 前，读取共同父目录 `CLAUDE.md`（没有则读 `AGENTS.md`）的 `## Agent skills` 段及其共享约定。若缺少约定，请用户在父目录环境会话按 `.matt/AI_SETUP.md` 第 1 节完成原版 setup，不在子仓初始化。其他环境缺项或升级也交由环境会话处理，就绪后从阻塞步骤继续。

优先采用用户点名的方法。自动流程只调用宿主允许模型调用的技能。若这类入口不可用，可读取工具包 `vendor/mattpocock/<短名>/SKILL.md` 及引用，注明是按随包参考执行；两者都不可用则报告缺项，停在该步骤。

> 手动入口：若用户要运行原版 `$mattpocock-skills:grill-with-docs` 或 `$mattpocock-skills:implement`，请用户分别在父会话或本端会话亲自发送该命令，待交付后再继续。其他仅限用户触发的技能同理；子会话提示词或读取副本不算启动原版。

- **已有行为异常**：用户直接报告故障、要求只排查或排查并修复，走下方「排障」，不先写功能 spec 或猜责任端。
- **新功能或行为变更**：进入「功能交付流程」，复用已有决定；用户指定的方法随单传给实现会话。
- **只验收已有版本**：`e2e.enabled: true` 时执行功能流程第 5 步，交付结果即停；只有用户也要求修复才将失败转入排障。关闭时说明未启用，不自行切换模式。
- **独立交付物**：调研结论用 `$mattpocock-skills:research`，一次性原型用 `$mattpocock-skills:prototype`，审查改动按[审查分流](references/review.md)选提交或补丁，PR 正文用 `$mattpocock-skills:pr`。交付即停；审查不是修复授权。需要委派时传该任务自己的范围与交付物，不套实现单。

`e2e.enabled` 取自共同父目录 `.matt/workflow.json`；需要判定 E2E 模式时若缺失或不是布尔值，请环境会话修复，不猜测。

## 排障：先复现，再决定是否派修

1. **复现和定位。** 调用 `$mattpocock-skills:diagnosing-bugs`，限定本阶段为诊断。记录原操作、预期和实际；在授权环境用最小能显示同一症状的检查跑出失败，按证据定位。已有可信复现和根因可复用。无复现就列已尝试的检查，索取脱敏日志、数据或可复现环境；根因未证实不猜端派修。关闭 E2E 仍可用本端测试、HTTP 等检查，不自行开启 Midscene。
2. **以用户授权划界。** 只排查或仅报告异常：交付复现方法、证据、已证实的根因或仍未知之处，到此为止，不改产品代码。要求修复且已定位：按[派单模板](references/dispatch.md)将故障预期、失败证据、本端测试边界及起始 SHA 派给责任端；优先复用原会话，没有则新开。两端均有偏差分别派，夹具、登录或用例问题留在父层按授权处理。
3. **复验原症状。** 在修复版本上重跑最初的复现，并核对本端回归测试和审查。启用 E2E 时再对实际版本组合重跑相关 case；关闭时注明未执行 E2E。原复现未跑、仍失败或仅替身通过，如实列为未验证或仍失败，不宣称已修好。

## 功能交付流程

1. **澄清需求。** 父会话直接用 `$mattpocock-skills:grilling` 澄清无法从路由、请求、后端 handler 和仓库指令推断的业务决定；涉及新术语或架构决定时用 `$mattpocock-skills:domain-modeling` 在父层记录。已有决定不再询问。
2. **确定开发和测试依据。** 父会话从 `spec/full-stack.md` 建立 `spec/<需求>.md`。公共部分是两端唯一的业务和接口契约：记录契约版本、成功和失败响应、场景 ID 与可观察预期。仅开发时用本端测试验证这些场景，不编写 E2E 用例；即使旧模板有 YAML 列也可省略。只有启用 E2E 时才把场景 ID 映射到 `e2e/cases/*.yaml` 的具名 case，并记录合成数据与清理方式。
3. **只派需要改代码的端。** 按[派单模板](references/dispatch.md)传入同一公共 spec 修订、本端范围、场景 ID、已确认的公开测试边界和本端起始 SHA。简单需求用同一文档的角色小节即可；复杂需求可拆单，契约仍只维护在公共部分。登记会话引用；无法启动时交付待派提示词。
4. **独立交接。** 逐端登记实际版本或补丁、测试、审查及未验证项。测试失败或审查未完成则报告阻塞。仅开发模式在相关端完成交接后报告「开发完成；按项目配置未执行 E2E」，不宣称联调通过；启用 E2E 才继续。
5. **验收实际组合。** 按父目录 `.matt/AI_SETUP.md` 核对运行服务的版本，用真实浏览器、授权测试账号、真实测试后端和合成数据执行相关 YAML，核查可见断言、持久化或跨端读回。向用户报告实际版本对、各场景的通过/失败/阻塞结果和本地私有报告位置。仅通过 mock 或缺少前提的场景标记为待真实验收。
6. **验收失败。** 在修复授权范围内转入「排障」，带上版本对、失败 case 和脱敏证据，不重复准备已有复现。若需变更契约，先确认业务决定，再同步 spec、YAML 和两端任务。
