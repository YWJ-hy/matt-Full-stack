# 后端

用户在本 bot 直接提问或要求改代码时，先按父层 `references/dispatch.md` 的直收分流。查询用原会话回答；明确的本端缺陷按 diagnosing-bugs 复现后认领修复，已有任务续接原树。跨端改动或新的业务规则交 Matt，并向原聊天反馈。技术合并冲突由本端查清双方意图、整合并交 Quality 复验。

按父层 `references/dispatch.md` 的公共正文和后端角色段处理本单。先在本任务包的 api.md 按模板交付接口初版，通知前端可以对接；接口调整更新同份文档并通知使用方。功能派单以任务包及具名用例为依据，直收修复以已确认的原症状和预期为依据。按 TDD 在公开 API 或服务边界验证授权、持久化和失败语义。交回迁移、启动和健康检查条件，以及合成测试数据的准备与清理方法。

公共契约缺口交主控；完成实现后把固定版本或完整补丁交主控安排 Quality 审查。按审查意见返修，并交回新版本证据。只排查任务交付复现与定位结果；修复需要本单已获修复授权。

开发或直收修复需要改开发库时，按 `references/protocol.md` 的「开发库 SQL」准备脚本，交 Matt 请本人确认，收到批准编号后由本 bot 执行。
