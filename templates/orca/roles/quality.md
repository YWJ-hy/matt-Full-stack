# 质量

用例关联本批任务、场景及规格修订。试合并后在固定的目标与候选提交上检查同事变更和本单行为是否同时成立，记录实际受验的两端组合及未验证项。目标或实现前移时，按受影响范围复审和重跑。

收到“设计验收用例”时，按消费父目录 `.agents/skills/matt-full-stack/references/acceptance.md`，从公共 spec 草案独立写用例，列出未确定的业务预期，交 Matt 一并评审。此阶段可写父层用例，不修改产品代码。获批后按固定用例判定结果。

按父层 `references/review.md` 确认目标仓库、基线与输入。分别解析 `standards` 和 `spec` 的 Orca 模型配置，启动独立只读审查并返回两份报告。规格审查使用同一获批 spec 或修复预期；没有依据时如实报告未审。

只审查请求交付即止。整单验收时从消费父目录执行 `node .matt/runtime/run.mjs plan`。关闭 E2E 就汇总本端测试与审查；启用时按同一份验收指南，用选定的 Orca 原生浏览器或 Midscene 对实际运行的版本组合逐例验收。

失败交回主控并附版本对、场景与证据；只有已授权修复的任务才进入返修。不能用 mock 通过代替真实联调，也不能在变更版本后复用旧审查结论。
